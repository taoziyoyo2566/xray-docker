### Two unresolved terms in the GeoLite EULA

The EULA version dated **2026-02-12** contains two terms that attribution alone
does not satisfy. Both are recorded here as known, unresolved risk.

**Staleness.** Verbatim:

> You shall cease use of and destroy (i) any old versions of the Services
> within thirty (30) days following the release of the updated GeoLite
> Databases

`geoip.dat` enters this image inside the Xray release zip and is a snapshot of
whatever MaxMind data the generating project held on that release date. It is
never refreshed in place, so the copy in any published tag exceeds thirty days
almost immediately. **Deleting old image tags would not fix this**: the current
stable tag carries data from its own release date and ages the same way. Only
changing *where the data comes from* — not bundling it, or fetching current
data at build time on a cadence shorter than thirty days — would address the
term on its own merits.

**Disclosure.** Verbatim:

> you will not disclose the Services to any third party without notifying
> MaxMind of the anticipated disclosure and obtaining MaxMind's prior written
> consent to the disclosure.

Read strictly, this makes public redistribution of GeoLite-derived data
conditional on MaxMind's consent — a condition that would apply to the whole
chain above this image, not only to this image.

**Whose position is what.** MaxMind's own answer is broad. Its support
documentation states that "Anyone who uses the GeoLite databases or GeoLite web
services is covered by the GeoLite End User License Agreement", and that "If you
share the GeoLite Databases or GeoLite Data with others, you need to hold others
to the same or substantially similar requirements to those imposed on you in the
GeoLite End User License Agreement". Read that way, use alone brings a recipient
under the terms, whether or not they ever saw them.

The open question is not what MaxMind asserts but whether it holds: these are
*contract* terms, and this project never obtained data from MaxMind, never
assented to that agreement, and receives a derived dataset in a different format
from an upstream release artifact. Whether such terms bind a non-assenting
downstream recipient of a derived dataset is a legal question, not an
engineering one. **Do not read the paragraph above as a compliance opinion in
either direction** — the terms are recorded so that whoever decides does so with
them in view.

What this image does do, on the assumption that the obligations travel: it
carries the named MaxMind attribution, and it tells its own recipients to
preserve that attribution and to impose equivalent terms downstream. That is
what an upstream licensee is required to pass on. It is not evidence that
recipients of a public, anonymous registry pull are in fact bound.

**If you need to avoid the question entirely:** mount your own directory over
`/usr/local/share/xray`, or set `XRAY_LOCATION_ASSET` to a path you control.

> **Why `-only` and not `-or-later`:** SPDX deprecated the bare `GPL-3.0`
> identifier; its current equivalents are `GPL-3.0-only` and `GPL-3.0-or-later`.
> `v2ray-rules-dat` ships a plain GPL-3.0 `LICENSE` file with no accompanying
> "or any later version" grant. (The "any later version" wording inside that
> file is the GPL's own *How to Apply These Terms* appendix, which is present in
> every copy of the license and is not a statement by the project.) A bare
> license file is conventionally read as **only**, which is also what SPDX
> itself named the deprecated `GPL-3.0` identifier — so this is a
> meaning-preserving change, not a new assertion. Revisit if upstream states a
> version policy.

### Corresponding Source

The image asserts `GPL-3.0-only` in `org.opencontainers.image.licenses`, both as
a per-platform image config label and as an index annotation. If
GPL-3.0 does apply to these files, GPLv3 requires that a non-source distribution
be accompanied by the license text and by access to the corresponding source.
Both are provided:

- The GPL-3.0 text ships at `/usr/share/licenses/geodata/GPL-3.0.txt`.
- The generating projects and their inputs are the public repositories named
  above. Equivalent access to that source is offered to every recipient of
  this image, through those same repositories, at no charge.

## Notes for maintainers

- The geodata files ship **inside** the official Xray release zip; they are not
  fetched separately. Their licenses therefore apply to every image build, and
  the chain is only as stable as Xray-core's asset workflow — re-verify it when
  that workflow changes.
- `geoip.dat` carries the strictest obligation in the image: a named-attribution
  requirement to MaxMind that survives redistribution. Removing the MaxMind
  attribution line from `docker-build/NOTICE` would breach the GeoLite EULA.
- Changing the geodata source (for example to a community rules set) changes the
  obligations recorded here — update this file, `docker-build/NOTICE`, the
  README's Licenses section, and the license expression in the same change. That
  expression has **one** source: the `licenses=` line in
  `docker-build/index-annotations.sh`. `.github/workflows/build-image.yml` reads
  it back through `index-annotations.sh --licenses` and the index annotations
  emit it directly, so editing the workflow changes nothing — edit the script.
- When the Dockerfile's asset layout changes, keep the upstream `LICENSE` in
  the image. Removing it would drop the MPL-2.0 notice required for
  redistribution. The same applies to `/usr/share/licenses/geodata/GPL-3.0.txt`
  for as long as the image asserts `GPL-3.0-only` in its licenses label: dropping
  one without the other leaves the assertion unbacked.
- The two GeoLite EULA terms above are **open risk, not closed items**. Do not
  downgrade the Status block to "resolved" on the strength of a documentation
  change; only a change of geodata source, or a legal review, closes them.
